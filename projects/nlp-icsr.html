NLP-Based ICSR Information Extraction

A synthetic-data project comparing traditional machine learning and FLAN-T5 for extracting safety information from CIOMS and FDA MedWatch reports into standardized ICSR fields.

TypeAcademic group project
Dataset130 synthetic cases
ModelsTraditional ML · FLAN-T5
DomainPharmacovigilance NLP

Overview

Exploring automated conversion of safety forms into standardized ICSR data.

Pharmacovigilance case processors manually review report forms and enter patient, reporter, product, event and narrative information into safety databases. This project evaluated whether NLP approaches could extract information from CIOMS and FDA MedWatch documents and map it into a standardized ICSR-oriented dataset.

View project repository
Data ethics: The project used 130 synthetic cases—30 CIOMS and 100 MedWatch forms. No real patient or confidential safety data was used.

Problem

Different forms, inconsistent fields, one standardized safety record.

CIOMS and MedWatch forms organize information differently, while downstream safety systems require consistent structured fields. The project therefore needed to handle form extraction, text normalization, field alignment and model evaluation—not just document classification.

Challenges

  • Structured and narrative content in the same document
  • Missing, optional or differently named fields
  • Medical synonyms and domain-specific language
  • Multiple values within products, events or histories
  • Evaluation across forms with different layouts

Target output

  • Patient and reporter fields
  • Suspect product information
  • Adverse event terms and dates
  • Seriousness and outcome indicators
  • Case narrative and source metadata
  • Unified ICSR-standard CSV structure

Evaluation

Measure the real pipeline, not a manually recreated result.

The project calculates metrics, case comparisons, tables and visualizations from the current documents, generated PDFs, trained models and actual prediction outputs. Test fixtures may verify code behavior, but synthetic test values are not presented as project results.

Results and interpretation

Traditional ML was stronger overall; transformers showed contextual potential.

The traditional pipeline achieved the better overall performance in the project, which is reasonable for a small, highly structured synthetic dataset with repeatable field patterns. FLAN-T5 was more computationally demanding and showed potential for complex narrative mapping, but a larger and more varied dataset would be needed to evaluate its advantage fairly.

Interpretation: This is a proof-of-concept and educational system, not a validated production pharmacovigilance application. Human review, validation, audit trails, privacy controls and regulatory-system integration would be required before operational use.

Production perspective

How the proof of concept could evolve.

  • Add document classification and layout-aware extraction for scanned and non-fillable forms.
  • Introduce medical dictionaries and controlled terminology mapping for drugs and events.
  • Build confidence scores and human-in-the-loop review queues.
  • Validate required ICSR criteria before creating a downstream case.
  • Track source-to-field provenance and maintain an immutable audit log.
  • Evaluate protected deployment, PHI handling, model drift and bias.
  • Integrate with a safety system only through validated, governed interfaces.
