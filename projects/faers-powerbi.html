FAERS Post-Market Safety Dashboard

A Power BI portfolio project built from public FDA FAERS ASCII files to explore report volume, seriousness, outcomes, geography, drug–reaction combinations, disproportionality and detailed product safety profiles.

PlatformPower BI PBIP
DataPublic FDA FAERS ASCII
ModelCases-centered relational model
FocusPost-market safety analytics

Overview

Making a complex public safety dataset easier to explore.

The project uses quarterly FDA FAERS ASCII files and presents the analysis as a multi-page Power BI report. It is designed as a pharmacovigilance and healthcare-analytics portfolio, not as a validated signal-management system. The dashboard helps users move from an executive view of reporting patterns into country, drug, reaction and report-level detail.

Public-data boundary: FAERS is a spontaneous-reporting system. The dashboard supports exploration and hypothesis generation; it does not establish incidence, prevalence or causality.

Data and model

Quarterly FAERS tables organized into an analysis model.

The Power BI model loads and transforms core FAERS ASCII files into tables for Cases, Drugs, Reactions, Outcomes and Report Sources. Lookup tables support cleaner drug and reaction filtering, while a country lookup supports both occurrence-country and reporter-country analysis.

Report pages

Five connected views for progressive analysis.

FAERS Safety Overview

High-level report volume, seriousness, outcomes, trends and key filters for an executive orientation.

Global Safety Reporting Map

Geographic distribution of reports with map-based comparison and country-level navigation.

Country Safety Profile

Focused country analysis, allowing users to compare reporting mix, outcomes, products and reactions.

Drug–Reaction Signal Analysis

Exploration of drug-reaction combinations, disproportionality measures, seriousness and time-related patterns.

Drug Safety Deep Dive

Drillthrough view for selected products, consolidating report characteristics, reactions, outcomes and temporal patterns.

Analytics

Measures and interactions built for investigation.

Analytical features

  • Report counts and serious-report proportions
  • Outcome and seriousness distributions
  • Time-to-event / reaction-onset analysis
  • Drug and reaction frequency
  • Disproportionality analysis using ROR and PRR
  • Country and reporter-source comparisons

User experience

  • Page navigation with normal, hover and selected states
  • Drillthrough to product-specific detail
  • Bookmarks and reset controls

Custom visualization

Deneb used where standard visuals were not enough.

The project includes Deneb/Vega-Lite work for a ridgeline-style visualization with year-month context. This demonstrates the ability to go beyond default Power BI visuals while still integrating with the semantic model, filters and report interactions.

Interpretation and limitations

Signal-oriented analytics requires careful language.

  • FAERS reports may be incomplete, duplicated, stimulated by publicity or influenced by reporting behavior.
  • Report counts cannot be used as exposure-adjusted rates because denominator data is unavailable.
  • ROR and PRR indicate disproportional reporting, not confirmed causality.
  • Results should be followed by clinical review, case assessment, literature review and additional evidence.
  • The project is a portfolio analysis using public data and is not an FDA or employer-endorsed tool.
