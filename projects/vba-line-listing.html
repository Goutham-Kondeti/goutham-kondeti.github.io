Configurable Excel VBA Line-Listing Splitter

A portfolio-safe recreation of an automation used to separate high-volume pharmacovigilance line listings by patient identifier while adapting to changing spreadsheet layouts.

ToolExcel VBA
InputVariable line-listing layouts
OutputFiles or worksheets by patient
Impact~1 day → ~5 minutes

Overview

Replacing repetitive patient-level splitting with a controlled, reusable workflow.

Vendor and business-partner line listings could contain more than 100 patient records. Each patient’s rows needed to be separated for downstream intake and case creation. Manual preparation was slow, repetitive and vulnerable to file-naming, row-selection and omission errors.

100+patient records possible in one source file
2 modesseparate workbooks or multiple worksheets
~5 minapplicable preparation after automation

Design challenge

The source structure was not always stable.

Why fixed macros failed

  • The patient identifier could appear in a different column.
  • The used data range could change from one line listing to another.
  • Some patients had multiple rows that had to remain together.
  • Different users needed either separate files or a single workbook with patient worksheets.

Design response

  • Prompt the user to select the complete source range.
  • Prompt the user to select the patient-identifier header.
  • Discover unique identifiers dynamically.
  • Preserve the header and all rows belonging to each patient.
  • Sanitize output names and handle cancellations or invalid selections.

Interactive workflow

Configuration happens through prompts—not code edits.

Select source range

The user selects the full line listing, including the header row, so the macro adapts to different row and column counts.

Select patient identifier

The user clicks the identifier header, removing the need to hard-code a column letter.

Choose output mode

The macro can create one workbook per patient or one workbook containing separate patient worksheets.

Validate and group

Blank identifiers are ignored, duplicate identifiers are grouped and every matching row remains with the correct patient.

Create controlled outputs

File and sheet names are sanitized, headers are retained and outputs are formatted for review.

Reliability controls

Automation with visible safeguards.

ControlPurpose
Range and header validationPrevents the user from selecting a patient field outside the chosen data range.
Blank-identifier handlingAvoids creating ambiguous patient files.
Case-insensitive groupingTreats equivalent identifiers consistently.
Safe file and sheet namesRemoves characters that Excel or Windows cannot use.
Unique worksheet namingPrevents naming conflicts after truncation.
Cancellation and error handlingRestores Excel settings and gives the user a clear message.

Business impact

Faster preparation with stronger consistency.

  • Reduced applicable line-listing preparation from approximately a full working day to about five minutes.
  • Reduced repetitive copying and the risk of assigning rows to the wrong patient output.
  • Made the solution reusable across different patient-identifier columns and source ranges.
  • Supported a controlled fallback when vendor template changes disrupted system-level automation.
  • Demonstrated the ability to translate a pharmacovigilance operational bottleneck into a practical technical solution.

Limitations and next steps

Appropriate controls still matter.

The macro should be validated against the current line-listing structure before production use. Future improvements could add a preview screen, row-count reconciliation, exception logs, duplicate-file handling, protected templates and configuration profiles for approved vendor formats.
