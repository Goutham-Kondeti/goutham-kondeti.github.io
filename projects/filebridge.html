The workflow behind the product

Diagnostic outputs needed a dependable handoff between network shares and the local clinical import workflow. The earlier script-based approach established the recurring copy procedure.

Why build an application

FileBridge brought the file-transfer and naming work into a reusable application. The application grew directly from a recurring operational need in the clinical workflow.

A repeatable handoff

Clear source and destination rules, consistent naming and duplicate-aware movement connect each step of the file handoff.

01 / Define the handoff

One source. One destination.

A route gives each folder pair its own identity and monitoring state. Local folders and network shares use the same route model; connection testing checks access before the transfer workflow.

02 / Make the rule explicit

Filter, wait, then transfer.

Include and exclude patterns, a file-ready delay, Copy or Move and a duplicate policy express what should happen to each eligible file. Separate timing controls make the recurring scan behavior visible.

03 / Keep the result visible

History survives the handoff.

The dashboard shows current activity. Searchable SQLite transfer history preserves completed and failed outcomes, supporting review even after another application consumes a delivered file.

The build

From recurring need to reusable software.

The recurring clinical file-copy task was the starting point. The application separates route configuration, file eligibility, transfer execution and persistent history. It is built for Windows with C#/.NET, WPF and SQLite; the public project includes isolated temporary-folder smoke tests.
